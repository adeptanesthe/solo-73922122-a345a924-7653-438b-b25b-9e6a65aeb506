# 冲压机冲次声音核对

值班员上传**正常循环参考录音**与**待检循环录音**，系统从音频中提取冲击并按参考节奏匹配，自动标出**漏冲对应的参考冲次**与**多冲的实录时刻**，网页可定位播放标出的时段。

换模后两种模具节拍相同、听录音容易选错参考时，可在**辨认模具**页输入 2～4 个模具编号、每种上传 3 段已确认正常的样音，再上传 1 段待辨认的完整循环，系统按**冲击频谱**辨认模具；辨认通过后可直接把该模具的一段样音填为核对页参考。

## 输入约定

- WAV（PCM）：16 kHz、16-bit、单声道，单个文件不超过 8 秒
- 参考录音：含 4～8 次清晰冲击，相邻冲击间隔至少 150 ms
- 待检录音：允许起始静音、整体响度变化、漏冲、多冲；正常冲次间隔相对参考允许 ±15% 变化
- 模具辨认：2～4 个不重复模具编号，每个模具恰好 3 段已确认正常样音 + 1 段待辨完整循环；每段录音至少含 1 次可检测冲击

## 判定规则

1. **冲击检测**：短时能量包络 + 自适应门限（门限跟随录音自身峰值，对整体响度变化不敏感）+ 局部极大值拾取。
2. **回声处理**：同一冲击 40 ms 不应期内的峰（含衰减拖尾、回声）只保留最强一个，回声不计多冲。
3. **节奏匹配（动态规划）**：以参考冲次序号为基准做最优对齐，成本 = 漏冲数 + 多冲数；相邻匹配的累计时长须落在参考节奏 ±15% 窗口内。
4. **漏冲不错位**：漏冲只计一次成本，后续冲次仍按参考序号继续对齐，不会整体错位。
5. **歧义人工复听**：若多种归属具有相同的最优成本（同样满足节奏与最少漏/多冲），返回 `ambiguous`，网页给出醒目提示，不武断放行。
6. **无效音频不覆盖结果**：格式/时长/参考质量不合格时返回 400 且不写入状态，上一次有效结果原样保留。

## 模具辨认规则（按冲击频谱）

1. **冲击频谱指纹**：对每个冲击在其时刻附近取固定短窗（前 5ms、后 50ms，Hann 窗 + 1024 点 FFT，200Hz～6kHz 有效频带），逐冲击 L2 归一化后对全部冲击取平均并再次归一化。指纹只刻画频谱形状，因此**整体调高/调低音量（恒定增益）或在录音前加起始静音，辨认归属不变**。
2. **留一法校准匹配范围**：每种模具轮流留出 1 段样音、仅用其余样音构成参考指纹去辨认它；留一过程中本模具各折的自相似度最小值/最大值即该模具的**匹配范围**。
3. **不可推荐模具**：某模具的样音只要有一段被错认或归属不明（与非本模具相似度差距 ≤ 0.02），该模具标记为留一未通过——**仍参与比较，但不能被推荐**。
4. **放行条件（须全部满足）**：
   - 最佳相似度落在该模具匹配范围内（下限允许 0.02 容差；与所有模具都不像时优先判为「超范围」而非归属不明）；
   - 待辨录音在所有模具中**唯一**最佳，与第二名相似度差 > 0.02；
   - 该模具通过留一验证。
5. **失败保留参考**：不满足任一条件即辨认失败，返回可读原因（`ambiguous` 归属不明 / `out_of_range` 超出匹配范围 / `mold_not_recommendable` 模具留一未通过），当前核对参考与上一次辨认结果均保留不变。
6. **回填参考**：仅辨认成功时，网页允许选取该模具的任一段样音，自动填入「冲次核对」页的参考录音输入框。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

录音与结果数据保存在命名卷 `press-data`（容器内 `/data`）。

## 本地开发（无 Docker 时）

```bash
python3 -m pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 自定义数据目录：APP_DATA_DIR=/some/dir uvicorn app.main:app
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/inspect` | multipart 表单字段 `reference`、`test`（均为 .wav），返回核对结果 |
| `GET` | `/api/result/last` | 最近一次有效核对结果（无结果时 404） |
| `DELETE` | `/api/result/last` | 清除内存中的最近核对结果 |
| `POST` | `/api/identify-molds` | 模具辨认：可重复字段 `mold_ids`（2～4 个）、样音 `sample_<编号>_<1..3>`、待辨录音 `unknown`；输入不合格返回 400，辨认不通过返回 200 且 `decision=failed` |
| `GET` | `/api/identification/last` | 最近一次辨认结果（无结果时 404） |
| `DELETE` | `/api/identification/last` | 清除内存中的最近辨认结果 |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/data/uploads/{name}` | 回传已上传录音（含模具样音/待辨录音），供网页播放器与回填参考使用 |

结果关键字段：`verdict`（`ok` / `defect` / `ambiguous`）、`missed[].ref_index`（漏冲对应的参考冲次，从 0 开始）、`missed[].expected_time`（待检中预计应出现的时刻）、`extras[].time`（多充实录时刻）、`matches`（匹配明细）、`warnings`（回声抑制、歧义等提示）。

辨认结果关键字段：`decision`（`identified` / `failed`）、`identified_mold`、`reason_code`（`unique_match` / `ambiguous` / `out_of_range` / `mold_not_recommendable`）、`reason`（可读原因）、`ranking`（各模具相似度、是否在范围内、留一是否通过）、`calibration`（每模具匹配范围与逐折留一明细）、`molds[].sample_urls`（用于回填参考的样音地址）。

python3 -m pytest tests/ -q

python3 scripts/gen_demo.py /tmp/demo

python3 scripts/gen_mold_demo.py /tmp/mold_demo

## 目录结构

```
app/
  audio.py          WAV 校验与冲击检测
  matching.py       节奏匹配动态规划（漏冲/多冲/歧义）
  identification.py 冲击频谱指纹、留一法校准匹配范围、模具辨认决策
  service.py        核对/辨认服务与结果存储（无效输入不覆盖旧结果）
  main.py           FastAPI 路由
  static/           单页前端（冲次核对 / 辨认模具两个页签、波形标注、样音回填参考）
tests/              检测、匹配、辨认、端到端 API 测试（44 项）
scripts/            核对与模具辨认的演示 WAV 生成
```
